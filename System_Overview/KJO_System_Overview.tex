\section{Introduction}
%═══════════════════════════════════════════════════════════════════════════════

The KJO system controls a bi-propellant liquid rocket motor using nitrous oxide
(N\textsubscript{2}O) as the oxidizer and a liquid fuel with regenerative
cooling.  Four autonomous microcontroller units share control responsibilities:

\begin{itemize}[nosep]
  \item \textbf{Remote Control Unit (RCU)} --- handheld operator terminal.
        Sends commands over a 900~MHz LoRa radio link; displays system status
        on a 3.5\textquotedbl\ colour touchscreen.
  \item \textbf{Engine Management Unit (EMU)} --- mounted in the rocket.
        Receives commands from the RCU, actuates the Oxidizer Feed and Fuel Feed
        servos, reads all sensors, and coordinates the Fill valve and load-cell
        readings with the GSEMU and LCMU over a shared CAN bus.
  \item \textbf{GSE Management Unit (GSEMU)} --- mounted on the launch pad.
        Controls the Fill valve servo and the umbilical quick-release servo;
        coordinates the fill-to-target sequence with the LCMU and reports
        status to the EMU, both over the shared CAN bus. A separate,
        ground-referenced disconnect-sense line (not CAN) gives both EMU and
        GSEMU instant, protocol-independent detection of umbilical separation.
  \item \textbf{Load Cell Management Unit (LCMU)} --- mounted on the test
        stand. Measures Ox load during oxidizer fill (supporting GSEMU's
        fill-to-target sequence) and thrust during test-stand burns, logging
        both to microSD; answers CAN queries from EMU and GSEMU.
\end{itemize}

RCU, EMU, and GSEMU are based on the Adafruit Feather~M0 (ATSAMD21G18A,
48~MHz ARM~Cortex-M0+, 3.3~V logic); LCMU is based on the Adafruit
Feather~RP2040 Adalogger (dual-core Cortex-M0+, 133~MHz). All four run
firmware written in C++17 using the Arduino / PlatformIO framework.

\subsection{Fill Sequence}

EMU owns the entire fill session --- GSEMU has no fill state machine of
its own, it only opens/closes the Fill valve servo on command; LCMU only
answers weight queries. This replaced an earlier design where GSEMU
tracked progress itself (see the CAN protocol note in
Section~\ref{sec:architecture}).

\begin{enumerate}[nosep]
  \item Operator commands \cmd{BEGIN\_FILL} from the RCU.
  \item EMU (fresh start only --- a paused session skips this) sends
        \sw{CAN\_TARE} to LCMU.
  \item EMU sends \sw{CAN\_OPEN\_FILL\_VALVE} to GSEMU.
  \item N\textsubscript{2}O flows: GSE source tank~$\to$ Fill valve~$\to$
        QR servo~$\to$ umbilical~$\to$ check valve~$\to$ on-board
        oxidizer tank.
  \item EMU polls LCMU with \sw{CAN\_REPORT\_CURRENT\_WEIGHT} every
        200~ms, comparing the tare-relative reading against a per-motor
        target it holds locally (never sent to GSEMU or LCMU).
  \item Once the target is reached, EMU sends \sw{CAN\_CLOSE\_FILL\_VALVE}
        to GSEMU. \cmd{STOP\_FILL} (operator pause) does the same at any
        point; a later \cmd{BEGIN\_FILL} resumes without re-taring.
  \item The RCU polls fill progress locally from the EMU via
        \cmd{QUERY\_FILL\_PROGRESS} (LoRa) --- this is answered from EMU's
        own cached poll state, not a fresh CAN round trip.
\end{enumerate}

\subsection{Engine Firing Sequence}

Ignition is a 10-step sequence (\sw{Check\_Engine\_Start()}) that
establishes propellant flow \emph{before} firing the igniter --- reversed
from an earlier design that fired first. Fuel opens before Ox, since it
has the longer physical path to the chamber and needs the head start;
the igniter's solid starter motor only burns for a very short window
once lit.

\begin{enumerate}[nosep]
  \item Operator selects a source with \cmd{SET\_IGNITION\_SOURCE}
        (RCU / LCO / Airstart) and arms it with \cmd{ARM\_LAUNCH}
        (renamed from \cmd{ENABLE\_LCO\_CONTROL}).
  \item Operator commands \cmd{START\_ENGINE} (RCU source), or the armed
        LCO/Airstart trigger fires --- either way, EMU sends
        \cmd{ENGINE\_START\_ARMED} to the RCU unprompted the instant the
        sequence begins.
  \item EMU verifies Ox and Fuel are closed; if GSEMU is CAN-reachable,
        closes the Fill valve and waits for confirmation (protects the
        ground tanks from an open Fill valve during ignition).
  \item EMU releases the umbilical quick-release and waits for confirmed
        physical separation, then a fixed dwell.
  \item EMU opens the Fuel valve, waits for confirmed open plus a flow
        delay, then opens the Ox valve the same way.
  \item EMU fires the igniter relay --- the last step, once both
        propellants are already flowing.
  \item Proportional control commands (\cmd{OXIDIZER\_FLOW\_PROP},
        \cmd{FUEL\_FLOW\_PROP}) may be sent during burn to adjust mixture
        ratio.
  \item \cmd{STOP\_ENGINE\_FLOWS} closes both feed valves to terminate
        thrust.
\end{enumerate}

Any precondition or confirmation failure at steps 3--5 aborts the
sequence; see the EMU Reference for the full step table and failure
codes.

\subsection{Dump / Safe Procedure}

The \cmd{DUMP} command opens the Oxidizer Feed valve (EMU-controlled), venting
the on-board N\textsubscript{2}O tank pressurant through the combustion chamber.
There is no dedicated Dump valve.  The RCU Dump button has latching behaviour
--- a second press sends \cmd{STOP\_DUMP} and closes the Oxidizer Feed valve.

\subsection{Pressurization}

The on-board N\textsubscript{2}O tank is self-pressurizing (autogenous).  The
vapour-space pressure is communicated to the fuel tank via a dedicated
pressurization line, eliminating the need for a separate pressurant.

\subsection{RCU--EMU Radio Link}

The link uses the HopeRF RFM95W module (Semtech SX1276 chipset) operating at
915.0~MHz with 23~dBm transmit power.  Packets are simple binary structures
(see Section~\ref{sec:packets}).  The RCU sends a \cmd{HEARTBEAT} packet at
5-second intervals when no other command is pending; the EMU echoes a
\cmd{HEARTBEAT} response containing valve positions and battery voltage.  Link
loss is declared after 30~seconds without a response.

\subsection{EMU--GSEMU--LCMU CAN Bus}

EMU, GSEMU, and LCMU share one CAN bus (MCP2515 controllers, 1~Mbps,
node IDs EMU~=~1, GSEMU~=~2, LCMU~=~3) --- addressed command/response only,
no unsolicited broadcasts. This replaced an earlier wired GPIO CMD/STATUS
handshake that carried Fill-valve coordination directly between EMU and
GSEMU; that handshake's two lines (\sig{AUX\_IO\_1}/\sig{AUX\_IO\_2} on
EMU's MCP23X17 GPIO expander) are retired. Full command tables and protocol
details for each unit are in their own reference documents
(Section~\ref{sec:references}).

Separately, a ground-referenced disconnect-sense line on each side of the
EMU--GSEMU umbilical (not CAN) gives both units instant physical-disconnect
detection independent of bus traffic or timeout logic.

\section{Command Set}
\label{sec:commands}
%═══════════════════════════════════════════════════════════════════════════════

\subsection{Packet Structures}

Six binary packet types are used on the radio link (all defined in
\sw{KJO\_Command\_Defs.h}):

\begin{sloppypar}
\begin{itemize}[nosep]
  \item \textbf{Command\_Payload} (4 bytes, RCU$\to$EMU): \texttt{command}
        (1B), \texttt{param} (short, 2B), \texttt{terminator} (1B).  Used
        for most commands.
  \item \textbf{Command\_Return\_Packet} (4 bytes, EMU$\to$RCU):
        \texttt{command} (1B), \texttt{status} (bool, 1B), \texttt{r\_val}
        (short, 2B).  Returned for most non-heartbeat commands.
  \item \textbf{Heartbeat\_Command\_Packet} (1 byte, RCU$\to$EMU):
        \texttt{command} only --- the RCU already knows its own battery
        voltage locally.
  \item \textbf{Heartbeat\_Response\_Packet} (11 bytes, EMU$\to$RCU):
        \texttt{command} (1B), \texttt{EMU\_voltage} (float, 4B),
        \texttt{fill\_pct}, \texttt{ox\_pct}, \texttt{fuel\_pct} (int8,
        1B each), \texttt{qr\_connected}, \texttt{gsemu\_reachable},
        \texttt{lcmu\_reachable} (bool, 1B each). The last three come
        from EMU's own CAN presence cache, not a fresh query per
        heartbeat.
  \item \textbf{Fill\_Progress\_Response\_Packet} (9 bytes, EMU$\to$RCU,
        answers \cmd{QUERY\_FILL\_PROGRESS}): \texttt{command} (1B),
        \texttt{fill\_state} (1B: IDLE/IN\_PROGRESS/PAUSED/COMPLETE/
        ABORTED), \texttt{current\_weight\_lbm} (float, 4B),
        \texttt{percent} (int8, 1B), \texttt{seconds\_remaining} (int16,
        2B; $-1$ until enough flow has been observed to estimate).
  \item \textbf{RCU\_Status\_Response\_Packet} (9 bytes, EMU$\to$RCU,
        answers \cmd{RCU\_STATUS}): \texttt{command} (1B),
        \texttt{emu\_health}, \texttt{gsemu\_health}, \texttt{lcmu\_health}
        (uint16, 2B each, from live \sw{CAN\_GET\_HEALTH\_STATUS} queries),
        \texttt{gsemu\_reachable}, \texttt{lcmu\_reachable} (bool, 1B each).
\end{itemize}
\end{sloppypar}

\begin{sloppypar}
A seventh type, \textbf{Extended\_Heartbeat\_Response\_Packet}, exists
only for RCU\_UNIT\_TEST's bench-test telemetry panel and is never sent
to or parsed by production RCU.
\end{sloppypar}

\subsection{Command Table}

\begin{sloppypar}
Codes 1--35 below are production RCU's full command set. Codes 36--39
(\cmd{FIRE\_IGNITER}, \cmd{OPEN\_FILL\_VALVE}, \cmd{CLOSE\_FILL\_VALVE},
\cmd{EXTENDED\_HEARTBEAT}) exist only for RCU\_UNIT\_TEST, a separate
bench-test harness firmware with an expanded command set for exercising
individual actuators directly; production RCU never sends them and this
table omits their detail.
\end{sloppypar}
